# Курсовий проєкт

## **Система управління міжміськими автобусними перевезеннями та оптимізації маршрутів**

**Мова програмування:** Java
**Тип проєкту:** інформаційно-аналітична система з модулем оптимізації
**Предметна область:** міжміські пасажирські та багажні перевезення

### 1. Загальна постановка задачі

Бізнесмен **Т** закупив парк автобусів та планує створити мережу міжміських автобусних маршрутів. Автобуси здійснюватимуть регулярні перевезення пасажирів та їхнього багажу, а також, за необхідності, окремі перевезення багажу без пасажира. Планується функціонування до **30 маршрутів**, які охоплюють приблизно **50 міст**. Для автоматизації роботи підприємства необхідно розробити інформаційну систему, яка забезпечує ведення маршрутної мережі, продаж квитків, облік пасажирських і багажних перевезень, формування звітності та планування розкладу руху.

Особливістю проєкту є наявність **модуля оптимізації розкладу та диспетчеризації автобусів**. Система повинна не лише зберігати інформацію про маршрути та продажі, а й допомагати визначати розклад та розподіляти автобуси таким чином, щоб забезпечити виконання запланованих рейсів, врахувати обмеження транспортних засобів, час у дорозі, тривалість стоянок та можливість повторного використання автобуса після завершення попереднього рейсу.

---

# 2. Основна мета проєкту

Метою курсового проєкту є створення на Java програмної системи, яка об'єднує:

* облік міст і транспортної мережі;
* формування міжміських маршрутів;
* ведення розкладу;
* облік автобусів;
* продаж пасажирських квитків;
* оформлення багажних перевезень;
* облік завантаження автобусів;
* формування звітів;
* автоматизоване планування та оптимізацію розкладу.

Таким чином, проєкт поєднує **класичну інформаційну систему** з алгоритмічною задачею **Vehicle Routing / Dispatch Optimization**.

# 3. Основні об'єкти системи

У системі необхідно передбачити щонайменше такі сутності:

### Місто

Місто характеризується:

* ідентифікатором;
* назвою;
* координатами або іншою інформацією, необхідною для визначення відстані;
* переліком сполучень з іншими містами.

### Автобус

Для кожного автобуса зберігаються:

* державний номер або унікальний ID;
* модель;
* кількість пасажирських місць;
* багажна місткість;
* поточний статус;
* доступність у заданий період.

Статус автобуса може бути:

```text
AVAILABLE
IN_SERVICE
MAINTENANCE
UNAVAILABLE
```

### Маршрут

Маршрут визначає послідовність міст:

```text
Kyiv → Zhytomyr → Rivne → Lutsk
```

Для нього необхідно зберігати:

* номер маршруту;
* назву;
* список зупинок;
* відстані між містами;
* час проходження ділянок;
* тарифні зони або тарифи між містами;
* орієнтовну тривалість рейсу.

### Рейс

Важливо розділити **маршрут** і **конкретний рейс**.

Маршрут:

```text
Kyiv → Rivne → Lutsk
```

Рейс:

```text
Route 12
23.09.2026
Departure: 08:00
Bus: AA1234
```

Рейс повинен містити:

* маршрут;
* дату;
* час відправлення;
* автобус;
* список запланованих зупинок;
* статус рейсу;
* інформацію про продані квитки та багаж.

# 4. Продаж квитків

Система повинна дозволяти оформити квиток між будь-якими двома суміжними або несуміжними пунктами маршруту.

Наприклад:

```text
Kyiv → Zhytomyr
Kyiv → Rivne
Kyiv → Lutsk
Rivne → Lutsk
```

Для квитка необхідно зберігати:

* номер квитка;
* рейс;
* пасажира;
* місто відправлення;
* місто прибуття;
* місце;
* вартість;
* дату та час продажу;
* статус.

Можливі статуси:

```text
SOLD
CANCELLED
USED
```

# 6. Перевезення багажу

Система повинна підтримувати два варіанти:

### 1. Багаж пасажира

Багаж прив'язаний до придбаного квитка.

### 2. Окреме багажне відправлення

Багаж може перевозитися без пасажира.

Наприклад:

```text
From: Kyiv
To: Lutsk
Weight: 18 kg
Price: 320
```

Для багажного відправлення необхідно зберігати:

* номер відправлення;
* відправника;
* одержувача;
* пункт відправлення;
* пункт призначення;
* вагу;
* об'єм;
* вартість;
* рейс;
* статус доставки.

Стани:

```text
REGISTERED
LOADED
IN_TRANSIT
ARRIVED
DELIVERED
CANCELLED
```

# 7. Облік місткості автобуса

Автобус має два основних ресурси:

$$
\text{PassengerCapacity}
$$

та

$$
\text{LuggageCapacity}.
$$

Наприклад:

```text
Bus:
Seats = 52
Luggage = 1500 kg
```

При продажу квитка система повинна перевіряти наявність місць.

При оформленні багажу:

```text
currentLuggage + newLuggage <= capacity
```

Однак необхідно врахувати, що автобус може перевозити пасажирів, які виходять у різних містах.

Тому для кожної ділянки маршруту необхідно контролювати:

* кількість пасажирів;
* кількість багажу.

Наприклад:

```text
Kyiv ─── Zhytomyr ─── Rivne ─── Lutsk
       20 pax          35 pax
```

# 8. Звітність

Система повинна формувати звіти за різними параметрами.

### Продажі

* кількість проданих квитків;
* виручка;
* кількість пасажирів;
* популярність маршрутів.

### Багаж

* кількість відправлень;
* загальна вага;
* виручка;
* кількість доставлених відправлень;
* відправлення в дорозі.

### Автобуси

* кількість виконаних рейсів;
* кілометраж;
* завантаження;
* час роботи.

### Маршрути

* кількість рейсів;
* кількість пасажирів;
* середнє завантаження;
* дохід;
* середня ефективність використання автобуса.

# 9. Основна алгоритмічна задача

Ключовою частиною курсового є **оптимізація розкладу та диспетчеризації**.

Для кожного рейсу потрібно визначити:

* автобус;
* час відправлення;
* можливість виконання наступного рейсу після завершення попереднього;
* допустимі часові інтервали;
* обмеження тривалості роботи автобуса.

Наприклад:

```text
Bus A

08:00 ── Route 1 ── 11:30
                         │
                         ▼
                    turnaround
                         │
12:30 ── Route 5 ── 16:00
```

Система повинна не допустити ситуацію:

```text
Route 1: 08:00–11:30
Route 2: 10:30–14:00
```

для одного автобуса.

# 10. Clustered Vehicle Routing Problem

Для оптимізації мережа міст розглядається як граф:

$$
G=(V,E),
$$

де:

* \(V\) — множина міст;
* \(E\) — транспортні сполучення між ними.

Маршрути утворюють **кластери пов'язаних міст**, які необхідно обслуговувати певними рейсами.

Наприклад:

```text
             Zhytomyr
                 |
                 |
Kyiv ───────── Rivne ───── Lutsk
  |
  |
Cherkasy ───── Uman
```

Завдання системи — сформувати розклад рейсів і призначити автобуси так, щоб забезпечити всі необхідні перевезення з мінімальними витратами ресурсів.

# 11. Цільова функція оптимізації

Для спрощеної версії можна мінімізувати:

* загальний пробіг автобусів;
* кількість необхідних автобусів;
* час простою;
* кількість незадіяних місць;
* порушення часових обмежень.

У розширеній версії можна використовувати комбіновану функцію:

```text
Cost =
    α × total_distance
  + β × idle_time
  + γ × unused_capacity
  + δ × number_of_buses
  + penalties
```

Таким чином, студент повинен дослідити компроміс між різними критеріями.

# 12. Алгоритм оптимізації

Не обов'язково вимагати від студента реалізації складного MILP-солвера.

Основну версію можна побудувати на основі:

### Greedy algorithm

Спочатку обробляються найбільш важливі рейси, після чого для кожного шукається найкращий доступний автобус.

### Local Search

Після побудови початкового розкладу система намагається покращувати його:

```text
swap buses
change departure time
move trip
combine trips
```

### Simulated Annealing

Для підвищеного рівня можна реалізувати Simulated Annealing та порівняти його з жадібним алгоритмом.

# 13. Приклад роботи оптимізатора

Вхід:

```text
Buses = 8

Routes:
R1 Kyiv → Rivne
R2 Kyiv → Lutsk
R3 Kyiv → Zhytomyr
R4 Rivne → Lutsk
...
```

Початковий розклад:

```text
Bus 1: R1, R4
Bus 2: R2
Bus 3: R3, ...
```

Оптимізатор аналізує:

```text
distance
travel time
waiting time
capacity
conflicts
```

і формує покращений план:

```text
Bus 1:
08:00 R1
13:00 R4

Bus 2:
07:30 R3
11:30 R2
...
```
